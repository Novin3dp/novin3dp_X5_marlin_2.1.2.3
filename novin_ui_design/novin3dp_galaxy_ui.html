طراحی کامل منوهای Marlin برای برد MKS Robin Nano V3.1 و نمایشگر لمسی MKS TS35 (۴۸۰×۳۲۰). همه آیکن‌ها تک‌رنگ‌اند و همین صفحه آن‌ها را به بیت‌مپ ۱ بیتی (فرمت GREYSCALE1 مارلین) تبدیل می‌کند، پس چیزی که در پیش‌نمایش می‌بینید همان پیکسل‌هایی است که روی نمایشگر رسم می‌شود. پس‌زمینه کهکشانی با کد ساخته می‌شود و هیچ حجمی از فلش نمی‌گیرد.

کتابخانه آیکن ۱ بیتی

هر آیکن روی شبکه ۶۴×۶۴ طراحی شده، در اندازه انتخابی رسم می‌شود و با آستانه به ۱ بیت تبدیل می‌شود. ضخامت خط تا ۴۰ پیکسل ۲ پیکسل، تا ۶۴ پیکسل ۳ پیکسل و در ۸۰ پیکسل ۴ پیکسل است تا خطوط در ۱ بیت نشکنند. رنگ آیکن موقع رسم تعیین می‌شود، پس یک بیت‌مپ هم فیروزه‌ای، هم نارنجی و هم قرمز رسم می‌شود. روی هر آیکن بزنید تا کد C آن کپی شود.

تامبنیل QOI از جی‌کد OrcaSlicer

در فایل QOI-OrcaCube_v2_PLA_43m32s.gcode شما (تنظیم 48x48/QOI, 150x150/QOI) دو تصویر در ۱۴۵ خط اول هست. هر کدام بین ; thumbnail_QOI begin WxH LEN و ; thumbnail_QOI end قرار دارد و هر خطش با ; شروع می‌شود و ادامه‌اش base64 است. تصویر مکعب در این صفحه مستقیماً از همین داده‌ها و با همان مراحل کد C پایین باز شده است، پس بازکننده روی فایل واقعی شما آزمایش شده است.

QOI بدون پنجره و به‌صورت جریانی باز می‌شود. کل وضعیتش ۲۵۶ بایت است و هر پیکسل بلافاصله به RGB565 تبدیل و ردیف به ردیف روی نمایشگر رسم می‌شود. اندازه ۱۵۰ دقیقاً اندازه کادر صفحه چاپ است، پس تغییر اندازه لازم نیست.

// Streaming QOI -> RGB565. next_byte() returns the next base64-decoded byte
// from the "; " comment lines (4 chars -> 3 bytes). Skip the 14-byte "qoif" header first.
static uint8_t idx[64][4], px[4] = { 0, 0, 0, 255 }, run = 0;

bool qoi_next_pixel(uint16_t &color) {               // false = transparent pixel
  if (run) run--;
  else {
    const uint8_t b1 = next_byte();
    if (b1 == 0xFE)      { px[0] = next_byte(); px[1] = next_byte(); px[2] = next_byte(); }
    else if (b1 == 0xFF) { px[0] = next_byte(); px[1] = next_byte(); px[2] = next_byte(); px[3] = next_byte(); }
    else switch (b1 >> 6) {
      case 0: memcpy(px, idx[b1], 4); break;                                    // INDEX
      case 1: px[0] += ((b1 >> 4) & 3) - 2; px[1] += ((b1 >> 2) & 3) - 2; px[2] += (b1 & 3) - 2; break; // DIFF
      case 2: { const uint8_t b2 = next_byte(); const int8_t vg = (b1 & 0x3F) - 32;  // LUMA
                px[0] += vg - 8 + (b2 >> 4); px[1] += vg; px[2] += vg - 8 + (b2 & 0x0F); } break;
      case 3: run = b1 & 0x3F; break;                                           // RUN
    }
    memcpy(idx[(px[0] * 3 + px[1] * 5 + px[2] * 7 + px[3] * 11) & 63], px, 4);
  }
  color = RGB(px[0], px[1], px[2]);
  return px[3] >= 128;                                // transparent: keep panel + galaxy
}
  • فهرست فایل‌ها: برای هر کارت فقط خطوط توضیحی ابتدای فایل خوانده می‌شود و با رسیدن به اولین خط G-code جست‌وجو تمام می‌شود، پس فایل‌های بی‌تامبنیل هم سریع رد می‌شوند. کارت‌ها اول با نام و قاب خالی رسم می‌شوند و در هر دور حلقه UI یک تامبنیل اضافه می‌شود، پس صفحه هیچ‌وقت قفل نمی‌شود. هر تامبنیل ۴۸ حدود ۱۰ تا ۴۰ میلی‌ثانیه طول می‌کشد (USB کمی کندتر از SD).
  • بدون کش در RAM: هشت تامبنیل ۴۸×۴۸ در RGB565 می‌شود ۳۶ کیلوبایت، پس به جای نگه‌داشتن، هر بار از فایل خوانده می‌شوند.
  • جزئیات فایل: با لمس کارت، تامبنیل ۱۵۰ همان فایل خوانده می‌شود.
  • کِی رسم شود: فقط یک بار هنگام ورود به صفحه چاپ، مستقیم روی نمایشگر. به‌روزرسانی‌های دوره‌ای فقط درصد، زمان‌ها و دماها را دوباره رسم می‌کنند و به کادر تصویر دست نمی‌زنند. برای خواندن آن از یک SdBaseFile جداگانه استفاده می‌شود تا موقعیت خواندن فایل چاپ تغییر نکند.
  • اگر تامبنیل نبود: آیکن file در اندازه ۸۰ رسم می‌شود.
  • نمونه‌ها: در فهرست نمونه این صفحه فقط تصویر OrcaCube واقعی است. تصویر بقیه فایل‌ها (گلدان، برج دما و...) برای نمایش طرح کشیده شده‌اند و از همان مسیر RGB565 رد شده‌اند.

بر اساس آیکن‌ها و اندازه‌هایی که واقعاً در صفحه‌ها استفاده شده‌اند.

فونت‌ها

فقط سه اندازه از فونت NotoSans Medium که همین حالا در پوشه fontdata شما هست:

  • ۱۶ پیکسل، کامل: متن اصلی، برچسب‌ها و پیام‌ها. جایگزین ۱۴ فعلی در ui_480x320.h.
  • ۱۹ پیکسل، فقط ASCII: مقدارها و نام‌ها.
  • ۲۸ پیکسل، ASCII و °: عنوان صفحه و عددهای بزرگ.

دو فونت اضافه حدود ۱۰ تا ۱۴ کیلوبایت فلش می‌گیرند. فاصله ۲ پیکسلی حروف عنوان با یک خط کد در حلقه رسم حروف اضافه می‌شود.

پس‌زمینه کهکشانی بدون مصرف فلش

یک تصویر کامل ۴۸۰×۳۲۰ در RGB565 حدود ۳۰۰ کیلوبایت است و در این میکرو جا نمی‌شود. به جای آن هر پیکسل پس‌زمینه از دو چیز ساخته می‌شود: یک گرادیان عمودی آبی تیره و دو سحابی نرم. سحابی‌ها جداپذیرند، یعنی هر کدام از ضرب یک جدول X در یک جدول Y به دست می‌آیند و محاسبه‌شان ارزان است. پس‌زمینه هیچ ستاره یا نقطه‌ای ندارد و هر بار رسم دقیقاً همان تصویر را می‌دهد. پیش‌نمایش‌های این صفحه با همین الگوریتم ساخته شده‌اند. در Canvas::New() به جای پرکردن با COLOR_BACKGROUND این تابع را صدا بزنید. آیکن‌ها و متن‌ها فقط بیت‌های روشن را می‌نویسند، پس پس‌زمینه پشت آن‌ها دیده می‌شود.

// Marlin/src/lcd/tft/canvas.cpp
// RAM: bg_row 640 B + nebula tables 2 x (480 + 320) B  (or keep them const in flash)
static uint16_t bg_row[TFT_HEIGHT];                       // vertical gradient #040918 -> #091634
static uint8_t  neb_x[2][TFT_WIDTH], neb_y[2][TFT_HEIGHT]; // separable gaussians
static const uint16_t neb_col[2] = { RGB(34, 78, 170), RGB(52, 40, 140) };

static inline uint16_t blend565(uint16_t a, uint16_t b, uint8_t n) { // n = weight of b, 0..255
  const int ar = a >> 11, ag = (a >> 5) & 63, ab = a & 31,
            br = b >> 11, bg = (b >> 5) & 63, bb = b & 31;
  return ((ar + (((br - ar) * n) >> 8)) << 11) | ((ag + (((bg - ag) * n) >> 8)) << 5) | (ab + (((bb - ab) * n) >> 8));
}

uint16_t galaxy_pixel(uint16_t x, uint16_t y) {          // gradient + two soft nebulae, no stars
  uint16_t c = bg_row[y];
  for (uint8_t k = 0; k < 2; k++) {
    const uint8_t n = (neb_x[k][x] * neb_y[k][y]) >> 8;
    if (n) c = blend565(c, neb_col[k], n);
  }
  return c;
}

پنل نیمه‌شفاف و تیره‌کردن پشت پنجره

پنل‌ها رنگ #0E2850 با ترکیب ۵۰٪ روی کهکشان هستند و پشت پنجره‌های تأیید ۵۰٪ تیره می‌شود. هر دو بدون ضرب و با یک شیفت انجام می‌شوند:

static inline uint16_t half_blend(uint16_t a, uint16_t b) {
  return ((a & 0xF7DE) >> 1) + ((b & 0xF7DE) >> 1);
}
static inline uint16_t dim50(uint16_t c) {
  return (c >> 1) & 0x7BEF;
}

گوشه‌های گرد ۶ پیکسلی با رد کردن چند پیکسل گوشه در Canvas::addRect() ساخته می‌شوند. هیچ سایه یا درخششی در طرح نیست چون روی دستگاه گران است.

آیکن‌ها در فرمت مارلین

تغییرها نسبت به طرح‌های اولیه شما

  • LAYER به ارتفاع Z تبدیل شد، چون مارلین تعداد لایه‌ها را نمی‌داند.
  • زمان باقی‌مانده به SHOW_REMAINING_TIME و دستور M73 R از اسلایسر نیاز دارد؛ الان فقط SET_PROGRESS_PERCENT روشن است.
  • مکعب بزرگ صفحه Move جای خود را به موقعیت واقعی محورها داد: حدود ۳ کیلوبایت کمتر و اطلاعات مفیدتر.
  • LCD Contrast برای نمایشگرهای تک‌رنگ است؛ به جایش روشنایی صفحه آمد.
  • Retract حذف شد چون FWRETRACT خاموش است.
  • آیکن move صفحه اصلی به Prepare می‌رود و Move Axis داخل آن است، تا Home و پیش‌گرم هم یک لمس فاصله داشته باشند.

گزینه‌هایی که باید روشن شوند

  • PID_AUTOTUNE_MENU برای صفحه PID
  • Z_MIN_PROBE_REPEATABILITY_TEST برای دکمه M48
  • SHOW_REMAINING_TIME و SET_REMAINING_TIME برای زمان باقی‌مانده
  • DISPLAY_SLEEP_MINUTES و SOUND_MENU_ITEM برای صفحه Display
  • BED_TRAMMING_USE_PROBE (اختیاری) برای تنظیم گوشه‌ها با پراب؛ الان تست کاغذ است
